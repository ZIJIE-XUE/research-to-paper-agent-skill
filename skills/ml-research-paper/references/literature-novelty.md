# 文献搜集、阅读与创新检验

## 搜集与读取

先建立任务、方法、数据、评价、应用领域的中英文同义词；按精确问题分批检索。覆盖基础工作、近期直接竞争者、强基线、相反证据与失败复现。以论文、作者公开稿、出版社、会议/期刊官网及官方数据文档为事实依据；聚合索引和他人综述可供寻源。记录检索日期、查询式、来源与纳入/排除原因；一般定向综述不冒称系统综述或穷尽检索。

去重优先 DOI/稳定标识，其次规范化题名与作者年份。预印本和正式版互相关联，引用实际读过的版本。核对书目元数据和勘误/撤稿状态（能取得时）；打不开的链接不能标为已读全文。

每条 `literature/records.jsonl` 至少包含：

```json
{"id":"L001","title":"实际核验的题名","authors":[],"year":2026,"url":"实际来源URL","doi":null,"version":"preprint-v1","retrieved_at":"ISO时间","read_scope":"abstract|sections|full_text","locators":[],"claims":[],"author_limitations":[],"agent_inferences":[],"relevance":"与当前问题的关系","access":"available|restricted|unavailable"}
```

示例是字段说明，不能原样作为已完成记录。全文阅读卡记录问题、数据、方法、划分、基线、主要结果、不确定性、局限、可复现性、与当前工作的重合；重要结论附页码/节号/表号。自己做出的推断不得放入作者局限字段。

文献矩阵按研究问题、数据/时间、方法、对照、评价、局限与可比性组织。跨论文结果因数据和协议不同不能直接排名。引用库与阅读卡双向对应，正式引用前重新核对核心论断是否真由该来源支持。

## 六问创新检验

1. **作者局限**：原文明确说了什么？局限后来是否已有解决？
2. **证据/因果缺口**：评价目标需要因果识别吗？现有证据能排除什么，不能排除什么？不要给纯预测课题强加因果结论。
3. **替代机制**：改进能否由数据泄漏、预算差异、预处理、类别分布、规模或选择偏差解释？
4. **反向命题**：方法何时失效？简单基线何时足够？能否构造反例或边界条件？
5. **技术机会**：新数据、表示、约束、训练/评价方法可使什么旧问题变得可检验？复杂度要有目的。
6. **研究价值**：若结果成立或不成立，会改变谁的判断/方法/行动？计算与数据成本是否相称？

每个候选记录：主问题、最近邻、已知重合、可能增量、可反驳预测、最小实验、数据/计算条件和失败时的知识价值。选择一个主问题和少量必要子问题；不要把六问硬写成论文的六章。

反向检索必须尝试推翻“这是新的”。换模型名、换数据集、增加调参、补常规检验或代码跑通本身不能证明原创性。可以诚实定位为复制扩展、基准、系统评估或负结果。创新判定标记为 `supported_with_scope / incremental / replication / unestablished`，给出来源和检索边界，避免“全球首次”的无证据声明。

## 完成条件

主张依赖的核心文献已核验到足够范围；最接近工作已做具体比较；未知项和访问缺口有记录。若资源不允许全文核查，则缩小论断与交付范围，不通过填写模板伪装完成。
