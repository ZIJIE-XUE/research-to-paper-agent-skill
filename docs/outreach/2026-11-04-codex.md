# ML research skill for Codex: frozen experiments, evidence ledgers and resumable review

I maintain [ML Research & Paper](https://github.com/ZIJIE-XUE/research-to-paper-agent-skill), an independent MIT-licensed skill for using an agent across an ML study: literature, experiment design/execution, writing and revision.

The part I'd like Codex users to try is the handoff between **actually running an experiment** and **writing a claim about its results**:

- Freeze the protocol, code and declared input files before starting a queue.
- Run local training commands with per-job timeouts and a cumulative budget; keep failed jobs and logs.
- Reuse a successful job only after its output hashes match. Changed inputs or protocols require a new experiment ID.
- Bind pre-review/final reports to the manuscript, claim ledger and supporting files. Changed material invalidates downstream checkpoints.

There is a small offline demo that needs Python 3.10+ but no model API key, extra packages or dataset download:

```bash
git clone https://github.com/ZIJIE-XUE/research-to-paper-agent-skill.git
cd research-to-paper-agent-skill
python examples/quick_demo.py
```

It runs four synthetic classification jobs, verifies reuse and audits the registered execution receipts. This is a tool-chain example, not evidence of real-world model performance or a complete research paper. The public Windows/Ubuntu CI runs 28 tests plus this demo.

For the full workflow, install `skills/ml-research-paper/` in the agent's skill directory and invoke `$ml-research-paper` with a research task or a focused mode. The agent supplies scientific/source judgments; the scripts check file relationships, hashes and declared provenance. They don't prove data authenticity or semantic correctness, and aren't a sandbox. English/Chinese entry docs are included; detailed protocols are currently mainly Chinese.

I'd particularly value a minimal example of a **resume/handoff failure**, or feedback on which artifacts you would require before letting a new session reuse a result. If you try another host/runtime, please name it rather than assuming compatibility. Public or synthetic examples are welcome in the repo's Issues.

Disclosure: I maintain the project; the implementation, documentation and this introduction were prepared with AI assistance. This is a community project, not an OpenAI product.
