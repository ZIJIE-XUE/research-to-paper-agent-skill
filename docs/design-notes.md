# 设计依据与范围

本仓库提炼机器学习研究中的可复用操作经验。其目标是支持以后不同课题的研究，既有论文仅用于识别容易出错的流程环节；不把个别数据集、模型、历史结果、期刊或领域指标作为默认前提。

关键设计选择：

1. **研究主线与子问题分开。** 先定义问题和主要终点，避免后续实验或写作把更容易回答的子问题换成原问题。
2. **搜集与阅读交替。** 全文取得程度、原文定位、版本和自己的推断分别记录；“搜到”不等于“读过”。
3. **创新接受反证。** 最近邻检索专门寻找重合，允许复制扩展或创新未确立；常规实现与更多实验不自动升级贡献。
4. **计划与实测分开。** 先写研究提案和框架，结果产生后写正式结果，避免为了既有叙事挑选数据。
5. **实验有预算和不可变记录。** 计划、代码与输入变化产生新实验ID；保留失败和负结果。恢复必须验证已有结果。
6. **结论回到证据。** 区分效应大小、不确定性、实际用途、泛化与因果；一个技术检查通过只支持它的覆盖范围。
7. **审稿推动实质修订。** 用稳定问题编号和验收标准关闭问题，反复润色受预算和改进幅度约束。
8. **状态落盘。** 每阶段保存成果与版本关系，便于换模型、换会话、暂停或继续。

架构为模型无关的 agent 指令，加上无需模型 API 的本地工具。用户选择 GPT-6.1 Sol 与极高推理时，项目模板记录为偏好；实际可用模型/强度由宿主环境确定。官方模型说明确认该模型支持复杂专业工作、工具和技能；工作流适用性仍需由真实研究表现检验。参见 [OpenAI 模型说明](https://developers.openai.com/api/docs/models/gpt-6.1-sol)。

本技能不复制现有研究技能套件内容，也不要求安装 ARS 或 RD-Agent。可用时可按用户任务调用相关工具，但不会把第三方技能的阶段批准流程强加给本工作流。研究内自动推进、资源与外部动作的授权边界均以用户当前指令为准。

仓库中的测试检验工具行为，不验证模型能独立完成任意学术创新，也不构成真实论文的端到端复现。首次用于新课题时，应由 agent 按实际任务完成适配，并由作者评估主问题、数据权限和科学结论。

## v1.1：参照ARS后的改进

2026-10-29读取ARS及ARS-Codex的在线介绍，文档版本标注为v3.24.0。资料来自 [中文README](https://github.com/Imbad0202/academic-research-skills/blob/main/README.zh-CN.md)、[架构](https://github.com/Imbad0202/academic-research-skills/blob/main/docs/ARCHITECTURE.md)、[定位](https://github.com/Imbad0202/academic-research-skills/blob/main/POSITIONING.md) 及 [Codex发行版](https://github.com/Imbad0202/academic-research-skills-codex)。这是阅读功能介绍与设计思想后的独立适配，没有复制ARS源码、提示词、模式实现或文档段落。

采用的思想及本地落点：

- 按需入口：新增modes.md，覆盖研究、实验、写作、引用检查、审稿、修订和恢复；自然语言模式不冒充插件命令。
- 证据交接：pipeline新增passport导出，记录实际材料和哈希；不使用ARS材料护照schema，也不声称兼容其完整运行时。
- 审稿前/交付前检查：新增audit_integrity.py，将登记主张、引用关系、实际运行回执与当前产物关联；pipeline把核验文件纳入检查点。
- 修订追踪：先保存证据锚定意见，再修订，按原验收标准复审；问题编号和严重度有明确作用，不生成未经校准的录用分数。
- 信息流与边界：区分原始输入、核验结果、写作材料和审稿证据；不宣称脚本提供强制权限隔离。
- 过程记录：最终交付研究决策、方案变化、计算和核验覆盖，避免只交论文而丢失研究过程。

保留本项目的特点：agent为任务实现训练程序，运行器可在本地执行；常规研究步骤在已有授权内继续，不照搬ARS逐阶段确认机制。未移植其系统综述筛选、文献resolver、跨模型传输、代理拓扑、校准和插件包装；这些能力也未作为本项目已完成功能宣传。

v1.0检查点保留为历史记录，v1.1的review/final需要重新绑定完整性报告；旧报告没有相应绑定字段时会被标记失效。当前测试覆盖工具行为，不等于对ARS做对比评测，也不证明整个研究流程的科学质量。
