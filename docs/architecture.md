# 架构与质量检查

## 三层结构

1. **用户目标与研究协议**：确定课题、材料、权限和预算；agent按模式选择最小范围，建立数据与评价协议。
2. **研究产物与证据层**：问题、文献/引用台账、数据清单、冻结协议、运行结果、论文主张与审稿问题互相定位。
3. **确定性工具层**：pipeline保存版本关系；runner执行任务并留回执；integrity审计登记对象的结构与来源。三者均不调用模型API。

## 阶段产物

- scope：问题说明与任务/预算配置。
- literature：文献记录、阅读卡、矩阵和参考文献。
- novelty：最近邻重合、增量与可证伪设计。
- framework：论文框架和提案初稿。
- data：来源、处理、标签和划分。
- design：协议、配置、代码与正式计划。
- experiments：日志、指标、输出、冻结清单与回执。
- conclusions：结果汇总、主张台账和图表来源。
- draft：正式正文、表图、公式与引用。
- polish：编辑记录及事实保护检查。
- review：审稿前完整性报告、审稿意见与稳定问题台账。
- final：最终完整性报告、交付文件、材料护照、过程记录和剩余问题。

根据修改回到最早受影响阶段，重验必要下游；旧回执留在history，正文历史版本由agent保存。单阶段任务不要求伪造整条流程检查点。

## 检查含义与版本绑定

运行器success表示进程成功退出且所列输出契约通过。integrity pass表示登记主张、引用关系及来源的确定性检查没有阻断项；来源支持判断由agent实际阅读后登记。有效检查点表示文件及上游回执匹配。

这些结果均不证明数据真实、代码没有科学错误、事实抽取完整或创新成立。最终报告保留未知范围；同一模型多次判断不能当作独立验证。

审稿前报告绑定当前论文、台账、摘录与运行证据；final报告还绑定最终问题台账。review/final检查点纳入报告和全部核验文件的哈希，后续变化触发重验。材料护照导出当前状态和清单，不代替检查点。

## 信息流与协作

数据/训练读取必要原始输入；写作使用核验结果及必要文献；审稿读取冻结稿与足够证据。默认同一代理分阶段执行并说明局限。已获授权且宿主支持时，才使用隔离上下文工作者，并记录实际输入和覆盖。

这套约定不提供操作系统沙箱、网络拦截或子代理权限控制。完整性脚本不自动查询外部索引。对外查询/上传使用最少必要内容，遵循已有授权。
